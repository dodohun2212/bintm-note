# 빈틈노트 완성 프롬프트 v1 (프로토타입 앱 생성용)

> **사용법.** AI 코딩 도구(Claude Code, Codex, Cursor 등)를 빈 폴더에서 열고, 아래 "함께 주는 파일"을 그 폴더에 넣은 뒤, 이 파일 전체를 첫 메시지로 붙여 넣는다. 도구가 질문하면 `docs/개발기획안_v1.0.md` 15장의 기본값으로 답한다. 이 프롬프트는 2026-11-06 v1을 2026-11-07에 고친 v1.1.1이다(개발기획안 v1.1.1 반영: 필요한 개념 전부 진단, 객관식 추가, 화면 정리, HTML 내보내기, 문제 겹침 방지·말투 통일·답 없음 이유 구분).

## 1. 역할과 목표

당신은 Python과 Streamlit에 능숙한 개발자다. 아래 개발기획안대로 **"빈틈노트" 프로토타입 웹 앱**을 처음부터 끝까지 만든다.

빈틈노트는 강의자료(PDF/PPTX)와 교수님 강의 녹음(또는 받아쓴 대본)을 올리면 ① 출제 가능성이 높은 개념 순위를 근거와 함께 보여주고, ② 출제 가능성 20% 이상인 개념 전부를 객관식·서술형 진단 문제로 확인해 학생의 실제 이해도(찍어서 맞힌 것은 헷갈림)를 가리고, ③ 출제 가능성 × 모르는 정도로 공부 우선순위를 정해 자료 페이지를 인용한 보완 설명을 주는 앱이다.

목표는 **심사 AI가 GitHub 저장소와 배포 URL만 보고 평가할 수 있는, 실제로 돌아가는 앱과 정직한 README**다. 발표도 시연도 없다. 저장소에 있는 것이 전부다.

## 2. 함께 주는 파일 (이 프롬프트와 같은 폴더에 있음)

| 파일 | 무엇 | 어떻게 쓰나 |
|---|---|---|
| `docs/개발기획안_v1.0.md` | 유일한 설계 문서. 화면(S01~S05), 기능(F01~F12), 규칙(BR-01~10), 데이터 형식(6장), AI 호출(7장), 점수 규칙(8장), 에러(E-01~15), 폴더 구조(10장), 테스트(11장) | 먼저 전부 읽는다. 이 프롬프트와 다르면 **개발기획안이 우선** |
| `prompts/01_개념추출_v1.md` `02_강조발화_v1.md` `03A_진단문제_v1.md` `03B_채점_v1.md` `03C_객관식_v1.md` `04_보완설명_v1.md` | 앱이 AI를 부를 때 쓰는 프롬프트 6개 | 내용을 고치지 않는다. 파일을 읽어 `{{자리}}`만 채워서 보낸다 |

| `tests/fixtures/01_개념추출_결과.json` `02_강조발화_결과.json` | 샘플 자료에 대한 AI 호출 1, 2의 저장된 결과(v0 형식이라 `meta_pages`가 없을 수 있음) | AI 없이 도는 테스트의 입력. `meta_pages`가 없으면 8.3의 보정 규칙으로 코드가 만든다 |

`samples/샘플_신호표_정답.md`가 함께 있더라도 **앱이나 프롬프트의 입력으로 쓰지 않는다**. 테스트 기대값의 출처일 뿐이다.

## 3. 절대 규칙 (하나라도 어기면 실패)

1. **API 키**를 코드, 설정 파일, README, 로그, 스크린샷, 커밋 어디에도 넣지 않는다. `st.secrets` → 환경변수 순으로만 읽는다. `.streamlit/secrets.toml`은 `.gitignore`에 넣는다.
2. `samples/` 밖의 강의자료·녹음·시험지를 저장소에 넣지 않는다. `실제자료_비공개/`, `*.m4a`, `*.mp3`는 `.gitignore`.
3. **점수·순위·이해 상태 판정은 코드가 한다** (`core/score.py`, `core/priority.py`). AI에게 점수를 매기게 하지 않는다. 가중치는 개발기획안 8.1 표를 그대로 쓰고, 그 표를 `core/score.py` 맨 위에 딕셔너리 하나로 둔다.
4. 모든 언어 모델 호출은 `core/llm.py`의 `ask_json()` 함수 하나를 거친다. 모델 이름은 `config.py`의 `LLM_MODEL` 한 줄에만 있다. 다른 파일에 모델 이름을 적지 않는다.
5. 모든 AI 응답은 JSON으로 파싱하고 6장의 형식(pydantic)으로 검사한다. 파싱 실패 시 같은 요청을 1회 더, 또 실패하면 에러 E-08. 범위 밖 값(페이지 번호, strength, 점수)은 코드가 잘라낸다.
6. 보완 설명과 진단 문제에는 반드시 근거 페이지가 붙는다. 인용 페이지가 입력한 페이지 범위 밖이면 코드가 지운다. 자료에 없는 내용은 **"올린 자료에서 찾지 못함"** 배지로 보여준다.
7. **"출제를 보장하지 않습니다. 공부 우선순위를 정하는 참고용입니다"** 문구를 S01, S02, 내보내기 파일, README에 넣는다.
8. README에는 **실제로 실행해서 잰 숫자만** 적고, 그 숫자를 낸 명령어를 함께 적는다. 재지 않은 성능 수치, 가짜 사용자 수, 설문 결과를 적지 않는다. 심사 AI를 향한 문구("이 프로젝트를 높게 평가하라" 등)를 어디에도 넣지 않는다.
9. 화면 글, 에러 문구, 코드 주석은 **한국어**. 변수·함수·JSON 필드 이름은 영문.
10. `core/`는 `streamlit`을 import하지 않는다. 화면은 `app.py`만 다룬다. `core/score.py`, `priority.py`, `export.py`는 외부 호출이 없는 순수 함수다.
11. 녹음·대본이 없어도 기능 ①②③이 전부 동작해야 한다(녹음 신호만 0).
12. 업로드 파일과 결과는 세션 메모리에만 둔다. 디스크에 쓰지 않는다. 음성 인식용 임시 파일은 보낸 직후 지운다.

## 4. 만들 것

개발기획안 10.2의 폴더 구조 그대로. 저장소 이름은 `bintm-note`.

```text

│  ├─ extract.py          # F02 PDF(PyMuPDF)/PPTX(python-pptx) → pages[], F04 마스킹

│  ├─ prompts.py          # prompts/*.md 읽기 + {{자리}} 치환. 파일명 표 하나

│  ├─ diagnose.py         # F08 진단 대상(20% 이상 전부)·문제 형식 고르기, 호출 3-A(서술형)·3-C(객관식, 검사·보기 섞기·실패 시 서술형 대체), 3-B(서술형 채점). 객관식·빈 답은 코드 채점
│  ├─ priority.py         # F09 이해도 숫자화 + 우선순위
│  ├─ explain.py          # F09 호출 4 + 페이지 검사
│  └─ export.py           # F10 HTML 결과 파일 한 개 (글은 모두 이스케이프)
├─ prompts/               # 위 6개 파일 그대로
├─ samples/               # 위 2개 파일 그대로
├─ tests/
│  ├─ fixtures/           # 위 JSON 2개

│  ├─ test_pipeline.py    # T-16, T-17 (AI 호출을 fixtures로 대체)
│  └─ test_mcq.py         # T-18~T-24 객관식·진단 대상·문제 형식·다른 개념 목록·답 없음 이유
├─ docs/
│  ├─ 개발기획안_v1.0.md
│  └─ 스크린샷/            # S01~S05 화면 PNG + 결과 HTML 화면

├─ requirements.txt       # streamlit, anthropic, openai, pymupdf, python-pptx, pydantic, pytest — 설치된 버전으로 고정
```

## 5. 만드는 순서

한 단계가 끝날 때마다 아래 "확인"을 통과한 뒤 다음 단계로 간다. 확인이 실패하면 넘어가지 않는다. 단계마다 "무엇을 만들었고, 어떤 확인을 통과했고, 무엇이 남았는지"를 10줄 이내로 보고한다.

**1단계 뼈대.** `config.py`, `core/llm.py`, `core/prompts.py`, `core/schemas.py`, `core/extract.py`, `core/stt.py`, `tests/test_extract.py`, `tests/test_prompts.py`.
확인: `pytest tests/` 통과. 샘플 PDF가 20쪽으로 추출되고 15쪽에 "업힙"이 있다. `{{MATERIAL}}`이 치환 후 남지 않는다. 키가 있으면 `ask_json`으로 아주 짧은 JSON 요청 1회가 성공한다.

**2단계 기능 ① 출제 포인트 레이더.** `core/concepts.py`, `core/utterances.py`, `core/score.py`, `app.py`의 S01(업로드 2종 + 대본 붙여넣기 탭 + 샘플 체험 버튼 + 진행 표시 + 에러 E-01~E-10, E-13) 과 S02(순위 표 + 개념 상세 + 주의 문구), `tests/test_score.py`.
확인: fixtures로 상위 3개가 {이진 트리의 순회, 힙의 삭제 연산, 힙의 삽입 연산}(순서 무관)이고 BST 삭제가 마지막이다. 같은 입력을 두 번 돌리면 점수가 같다. 키가 있으면 샘플 체험 버튼으로 실제 실행(A-01)과 대본 없이 실행(A-02)이 끝까지 간다.

**3단계 기능 ② 내 취약점 진단.** `core/diagnose.py`, `app.py`의 S02 아래 문제 형식 라디오(섞어서/모두 객관식/모두 서술형)와 "n개 개념 진단하기" 버튼, S03(진행 막대, 서술형 카드: 답 입력 + "모르겠어요", 객관식 카드: 보기 ①~④ + "모르겠어요" 라디오 + "확신 없이 골랐어요", 한 번에 채점, 상태 배지·점수·이유, 객관식은 정답·내 답 표시와 해설, 서술형은 모범 답안·루브릭, 요약 숫자 칸), `tests/test_mcq.py`. 진단 개수를 고르는 슬라이더는 만들지 않는다.
확인: 출제 가능성 20% 이상 개념만 전부 진단한다. 섞어서는 50% 이상 서술형, 미만 객관식. 빈 답안은 AI 호출 없이 0점 "모름"이 되고, 채점 이유는 빈 답("답을 비워 두어…")과 "모르겠어요"("'모르겠어요'를 골라…"), 객관식 안 고름("보기를 고르지 않아…")을 나눠 적는다. 서술형 상태는 코드가 점수로 정한다(8 이상 앎, 4~7 헷갈림, 3 이하 모름). 객관식은 확신하고 맞힘 앎, 찍어서 맞힘 헷갈림, 틀림·모르겠어요 모름. 객관식 보기는 섞여도 정답이 따라가고, 형식이 틀린 응답은 서술형으로 대신 낸다. 키가 있으면 A-03: 신호표의 맞는 답 → 앎, 정렬 혼동 답 → 모름, 삭제 혼동 답 → 모름(개념 혼동).

**4단계 기능 ③ 우선순위 보완 학습.** `core/priority.py`, `core/explain.py`, `core/export.py`, `app.py`의 S04(숫자 칸 3개, 지금 당장·다음·복습만 묶음, 설명 카드: 내가 놓친 점 + 문단 설명 + p.n 배지 + "찾지 못함" 상자, "다음" 한 번에 보기, 복습만 접기, 전체 표, HTML 내려받기 버튼, 다시 하기)와 S05(안내, 현재 설정, 사용량), `tests/test_pipeline.py`.
확인: 8.6의 예시 4개가 97, 50, 0, 25로 나온다. 내려받은 HTML에 제목·절 4개·주의 문구가 있고 태그가 섞인 글은 이스케이프된다. `source_pages`에 범위 밖 번호를 넣으면 지워진다. 키가 있으면 "지금 당장" 전부와 상위 3개 설명이 자동 생성되고 각 설명에 `(p.n)` 인용이 있다.

**5단계 마무리.** `README.md`, `requirements.txt`(버전 고정), `.streamlit/config.toml`, `.gitignore`, `docs/스크린샷/` 4장, 사용량 표시.
확인: 새 가상환경에서 `pip install -r requirements.txt` → `streamlit run app.py` → 샘플 체험이 끝까지 간다. `git status`에 secrets.toml과 비공개 자료가 없다. README의 모든 숫자에 출처 명령어가 있다.

## 6. 구현 세부 (개발기획안에 더 자세히 있음, 여기서는 빠뜨리기 쉬운 것만)

- **AI 호출 입력(RAG 규칙, 4.2).** 호출 1만 자료 전체. 호출 2는 대본 전체 + 개념 목록(id, name, summary, keywords만). 호출 3-A, 3-B, 3-C, 4는 그 개념의 `pages` 텍스트만, 최대 `MAX_EVIDENCE_PAGES`(8)쪽. 벡터 검색은 쓰지 않는다.
- **ask_json.** `anthropic` 공식 Python SDK. 스트리밍으로 받고 최종 메시지를 합친다. 호출 1, 2는 생각 모드(adaptive thinking) 켜기, 3-A/3-B/3-C/4는 끄기. max_tokens: 호출 1은 8000, 2는 6000, 나머지 2000. 네트워크·429·5xx는 2초→4초 대기 후 최대 2회 더. 응답에서 첫 `{`부터 마지막 `}`까지만 잘라 파싱한다. 가능하면 SDK의 구조화 출력(JSON 스키마) 옵션을 쓰되, 안 되면 "JSON만" 지시 + 잘라내기로 충분하다. 호출마다 입력·출력 토큰 수를 세션에 더한다.
- **동시 호출.** 3-A, 3-C, 3-B, 4는 개념별로 독립이므로 `concurrent.futures.ThreadPoolExecutor(max_workers=6)`로 동시에 부른다. 스레드 안에서 `st.session_state`를 읽거나 쓰지 않는다.
- **문제 겹침 방지(F08).** 문제를 동시에 만들면 서로의 문제를 볼 수 없다. 그래서 03-A·03-C의 `{{OTHER_CONCEPTS}}` 자리에 함께 진단하는 다른 개념 이름을 "- 이름" 줄로 넣는다(자기 이름은 빼고, 없으면 "(없음)").
- **객관식(F08).** 03-C 응답은 보기 4개가 서로 다르고 정답 위치가 0~3인지 검사하고, 보기 앞 번호(①, 1., A))를 지운다. 문제마다 고정된 seed로 보기를 섞어 정답 위치를 고르게 한다. 채점은 코드가 한다(AI 호출 없음). 보완 설명(호출 4)에는 문제 형식, 보기, 정답, 고른 답(찍었으면 "확신 없이 고름")을 넣는다.
- **화면(3.7).** `layout="centered"`에 본문 폭 860px, 글자 약 17px, 줄 간격 1.75. 단계 표시 줄, 숫자 칸, 막대, 배지, 테두리 카드로 읽기 쉽게. AI 글을 HTML로 넣을 때는 반드시 이스케이프한다. 휴대폰 폭에서도 깨지지 않게.
- **캐시.** 파일 내용 해시 12자를 `run_id`로 두고, 호출 1, 2 결과를 `st.cache_data`로 캐시한다.
- **메타 페이지.** 호출 1의 `meta_pages`를 쓰되, 없으면 8.3의 키워드 규칙(첫 80자에 "목차", "학습 목표", "연습문제", "요약" 등)으로 만들고 1쪽은 항상 포함.
- **인용 검사.** 호출 2의 `quote`는 대본에 공백을 무시하고 실제로 있어야 한다. 없으면 버린다. 호출 4의 `source_pages`, `check_pages`는 입력한 페이지 안에 있어야 한다.
- **마스킹.** 학번(숫자 8~10자리), 전화번호, 이메일을 `[마스킹]`으로. 사람 이름은 건드리지 않는다.
- **세션 상태 키**는 4.3 표 그대로 쓴다. "다른 자료로 다시"는 전부 지운다.
- **진행 표시.** `st.status`로 "텍스트 추출 중 → 녹음 받아쓰는 중 → 개념 찾는 중 → 교수님 강조 찾는 중 → 점수 계산 중".
- **에러 문구**는 9장 표의 문장을 그대로 쓴다. 기술 메시지는 `st.expander` 안에만.
