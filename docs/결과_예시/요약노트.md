### 트리의 기본 용어 · 보통

`복습만` `출제 점수 32` `헷갈림`

트리는 '계층적인 관계를 표현하는 비선형 자료구조'이며, 예로 폴더 구조, 조직도, 가계도가 있다 (p.4). 루트(root)는 가장 위의 노드(A)이고, 부모·자식은 간선으로 연결된 위·아래 노드로 B는 A의 자식이면서 D·E의 부모이다 (p.4). 단말 노드(leaf)는 자식이 없는 노드(D, E, F)이고, 서브트리는 한 노드와 그 자손 전체이다 (p.4). 진단에서 정답은 골랐지만 확신이 없었던 개념이므로, 각 용어의 정의를 예시 노드와 짝지어 확인해 둔다 (p.4).

**핵심**

- 루트 = 가장 위의 노드(A), 단말 노드 = 자식이 없는 노드(D, E, F)
- 부모·자식 = 간선으로 연결된 위·아래 노드 (B는 A의 자식, D·E의 부모)
- 서브트리 = 한 노드와 그 자손 전체

**자주 하는 실수**

- 확신 없이 찍어서 맞힌 개념이므로, 한 노드가 부모이면서 동시에 자식일 수 있다는 점(B는 A의 자식, D·E의 부모)처럼 정의를 예시와 함께 구분해 두어야 한다

### 트리의 깊이와 높이 · 자세히

`복습만` `출제 점수 61` `앎`

깊이(depth)는 루트에서 그 노드까지의 경로 길이(간선 수)다 (p.5). 루트의 깊이는 0이고, E의 깊이는 2다 (p.5).

높이(height)는 그 노드에서 가장 먼 단말 노드까지의 경로 길이다 (p.5). 단말 노드의 높이는 0이고, B의 높이는 2이며, 트리의 높이는 루트의 높이와 같은 3이다 (p.5).

깊이는 위에서 세고, 높이는 아래에서 센다 (p.5). 교수님은 '깊이는 위에서 세고 높이는 아래에서 센다, 이것만 기억하세요.'라고 강조했다 (p.5). 같은 노드라도 깊이와 높이는 다를 수 있으며, 노드 E는 깊이 2, 높이 0이다 (p.5).

**핵심**

- 깊이 = 루트에서 그 노드까지의 경로 길이(간선 수), 루트의 깊이 = 0
- 높이 = 그 노드에서 가장 먼 단말 노드까지의 경로 길이, 단말 노드의 높이 = 0
- 트리의 높이 = 루트의 높이 (자료의 예에서는 3)
- 깊이는 위에서 세고, 높이는 아래에서 센다

**자주 하는 실수**

- 깊이와 높이를 서로 바꿔 센다. 교수님은 '이건 매년 헷갈리는 학생이 많아요.'라고 경고했다
- 같은 노드라도 깊이와 높이가 다를 수 있다는 점을 놓친다. 노드 E는 깊이 2, 높이 0이다

교수님 · 실수 경고: “이건 매년 헷갈리는 학생이 많아요.”

교수님 · 강조: “깊이는 위에서 세고 높이는 아래에서 센다, 이것만 기억하세요.”

### 이진 트리의 종류 · 보통

`복습만` `출제 점수 20` `헷갈림`

이진 트리는 모든 노드가 최대 2개의 자식(왼쪽, 오른쪽)을 가지는 트리이며, 포화·완전·편향 이진 트리로 나뉜다 (p.6). 포화 이진 트리는 모든 레벨이 꽉 찬 트리이고, 편향 이진 트리는 한쪽으로만 자식이 있는 트리다 (p.6). 완전 이진 트리는 마지막 레벨을 제외하고 꽉 차 있고 마지막 레벨은 왼쪽부터 채워지며, 힙에서 사용한다 (p.6). 교수님은 '이 중에서 완전 이진 트리, 이게 조금 있다가 힙에서 그대로 쓰입니다.'라고 강조했다 (p.6).

**핵심**

- 포화 = 모든 레벨이 꽉 참 / 편향 = 한쪽으로만 자식이 있음
- 완전 = 마지막 레벨을 제외하고 꽉 참 + 마지막 레벨은 왼쪽부터 채워짐 → 힙에서 사용
- 진단에서 찍어서 맞힌 부분이므로 세 종류의 정의, 특히 완전 이진 트리의 조건을 확실히 외운다

**자주 하는 실수**

- 진단에서 확신 없이 찍어서 맞혔으므로, 완전 이진 트리의 조건(마지막 레벨은 왼쪽부터 채워짐)을 포화·편향 이진 트리의 정의와 구분해 다시 확인한다

### 이진 트리의 순회(전위·중위·후위) · 자세히

`다음` `출제 점수 94` `헷갈림`

순회(traversal)는 트리의 모든 노드를 한 번씩 방문하는 것이다 (p.8). 루트(V)를 언제 방문하느냐에 따라 세 가지로 나뉜다 (p.8).

전위 순회(preorder)는 V → L → R, 중위 순회(inorder)는 L → V → R, 후위 순회(postorder)는 L → R → V 순서이다 (p.8). 후위 순회에서는 L과 R을 모두 방문한 뒤에 V를 방문하므로 루트가 맨 마지막에 나온다 (p.8). 예제 수식 트리의 전위 순회 결과는 + * a b - c d, 중위 순회 결과는 a * b + c - d, 후위 순회 결과는 a b * c d - + 이다 (p.9). 수식 트리를 후위 순회하면 후위 표기식이 된다 (p.9).

세 방법 모두 재귀로 간단히 구현되며, 코드에서는 print(n.data)의 위치만 V L R, L V R, L R V 순서에 따라 달라진다 (p.8, p.10). 노드 n개를 각각 한 번씩 방문하므로 시간 복잡도는 O(n)이다 (p.10).

**핵심**

- 순회 순서: 전위 V → L → R, 중위 L → V → R, 후위 L → R → V (루트 V를 언제 방문하느냐로 구분)
- 후위 순회는 L과 R을 모두 방문한 뒤 V를 방문하므로 루트가 맨 마지막에 나온다
- 예제 결과: 전위 + * a b - c d, 중위 a * b + c - d, 후위 a b * c d - +
- 시간 복잡도 O(n): 노드 n개를 각각 한 번씩 방문한다
- 교수님은 '트리 그림 하나 주고 세 가지 순회 결과 쓰라고 하면 딱 한 문제가 됩니다.'라고 강조했다

**자주 하는 실수**

- 후위 순회 결과만 쓰고 L → R → V 규칙을 함께 적지 않는다 (p.8). 진단에서 결과는 맞았지만 이 규칙을 언급하지 않았다.
- 후위 순회에서 루트가 마지막에 방문되는 이유(L과 R을 모두 방문한 뒤 V를 방문하기 때문)를 설명하지 못한다 (p.8).

교수님 · 시험 암시: “중위 순회 결과를 쓰는 문제, 이건 시험에 내기 좋죠.”

교수님 · 강조: “이 중에서 순회하고 힙 삽입·삭제는 중간고사 범위의 핵심이라고 미리 말씀드립니다.”

교수님 · 시험 암시: “트리 그림 하나 주고 세 가지 순회 결과 쓰라고 하면 딱 한 문제가 됩니다.”

### 이진 탐색 트리의 탐색과 삽입 · 자세히

`다음` `출제 점수 60` `헷갈림`

이진 탐색 트리의 탐색은 루트부터 시작해 키가 작으면 왼쪽, 크면 오른쪽으로 내려가는 것이다 (p.12). 코드에서 search_bst(n, key)는 n이 None이면 None을 반환하고, key == n.data이면 n을 반환하며, key < n.data이면 왼쪽, 아니면 오른쪽으로 재귀 호출한다 (p.12).

삽입은 탐색이 실패한 위치(None)에 새 노드를 붙이는 것이며, 그래서 항상 단말 노드로 삽입된다 (p.12). insert_bst(r, n)은 r이 None이면 n을 반환하고, n.data < r.data이면 r.left에, n.data > r.data이면 r.right에 재귀 결과를 연결한 뒤 r을 반환한다 (p.12). 예제는 빈 트리에 35, 18, 68, 7, 26 순서로 삽입하면 앞 슬라이드의 트리가 된다는 것이다 (p.12). 진단에서 삽입 위치를 26의 오른쪽 자식이라고 정확히 썼더라도, 35 → 18 → 26으로 내려가는 비교 경로와 탐색이 실패한 빈 자리(None)에 붙어 단말 노드가 된다는 이유까지 함께 써야 한다 (p.12).

탐색과 삽입의 시간 복잡도는 트리의 높이 h에 비례하므로 O(h)이다 (p.12). 균형이 잡히면 O(log n), 편향되면 O(n)이다 (p.12).

**핵심**

- 탐색: 루트부터 키가 작으면 왼쪽, 크면 오른쪽으로 내려간다 (None이면 실패)
- 삽입: 탐색이 실패한 위치(None)에 새 노드를 붙인다 → 항상 단말 노드
- 삽입 위치는 비교 경로(예: 35 → 18 → 26)와 빈 자리(None)에 붙는 이유까지 함께 쓴다
- 시간 복잡도 O(h): 균형이 잡히면 O(log n), 편향되면 O(n)
- 교수님은 '삽입 순서를 주고 트리를 그리라는 문제도 자주 나와요.'라고 강조했다 (35, 18, 68, 7, 26 순서 삽입 예제로 연습)

**자주 하는 실수**

- 삽입 위치(예: 26의 오른쪽 자식)만 답하고, 35 → 18 → 26으로 내려가는 비교 경로와 빈 자리(None)에 붙어 단말 노드가 되는 이유를 빠뜨린다

교수님 · 시험 암시: “삽입 순서를 주고 트리를 그리라는 문제도 자주 나와요.”

### 힙의 정의(최대 힙·최소 힙) · 자세히

`다음` `출제 점수 28` `모름`

힙(heap)은 완전 이진 트리이면서, 모든 노드가 힙 조건을 만족하는 트리다 (p.14). 최대 힙은 부모 ≥ 자식이어서 루트가 최댓값이고, 최소 힙은 부모 ≤ 자식이어서 루트가 최솟값이다 (p.14). 교수님은 '오늘의 핵심이에요.'라고 강조했다 (p.14).

힙은 완전 이진 트리이므로 배열로 표현하며, 부모 i의 자식은 2i, 2i+1이다 (p.14). 그림의 최대 힙은 루트 93 아래에 80, 75가 있고, 배열은 [0]을 비워 두고 [1]부터 [93, 80, 75, 50, 62, 70, 33] 순으로 저장한다(p.14 그림).

힙 조건은 부모와 자식 사이의 관계이고, 형제 사이의 순서는 없으므로 정렬된 것이 아니다 (p.14). 교수님은 '주의할 건 형제끼리는 순서가 없다는 거예요.'라고 경고했다 (p.14). 진단에서는 ④번을 골라 틀렸고 정답은 ③번이었으므로, 위 정의 문장을 선택지와 하나씩 대조해 다시 확인해야 한다 (p.14).

**핵심**

- 힙 = 완전 이진 트리 + 모든 노드가 힙 조건을 만족
- 최대 힙: 부모 ≥ 자식 → 루트가 최댓값
- 최소 힙: 부모 ≤ 자식 → 루트가 최솟값
- 형제 사이의 순서는 없다 (정렬된 것이 아님)
- 배열 표현: 부모 i → 자식 2i, 2i+1

**자주 하는 실수**

- 힙을 정렬된 트리로 착각해 형제 사이에도 순서가 있다고 생각한다
- 진단에서 ④번을 골라 틀렸다(정답 ③번). 힙의 정의 문장을 선택지와 하나씩 대조하지 않으면 같은 실수를 반복할 수 있다

교수님 · 강조: “오늘의 핵심이에요.”

교수님 · 실수 경고: “주의할 건 형제끼리는 순서가 없다는 거예요.”

### 힙의 삽입 연산 · 자세히

`복습만` `출제 점수 100` `앎`

힙의 삽입 연산은 ① 새 항목을 마지막 위치(배열의 끝)에 넣어 완전 이진 트리를 유지하고, ② 부모와 비교해 더 크면 부모와 교환하며 위로 올라가는 업힙(sift-up)으로 힙 조건을 회복하는 연산이다 (p.15). 최대 힙 코드에서도 insert 함수는 업힙으로 표시되어 있다 (p.17).

예시 그림에서는 85를 마지막에 추가한 뒤 50, 80과 차례로 교환하며 올라가고, 93보다 작으므로 정지한다(p.15 그림). 코드에서는 배열 끝에 append한 뒤 i가 1이 아니고 n이 부모 self.heap[i // 2]보다 크면 부모 값을 내려 옮기고 i = i // 2로 올라간다 (p.17). 이 코드에서 인덱스 0은 사용하지 않는다 (p.17).

트리 높이만큼만 올라가므로 시간 복잡도는 O(log n)이다 (p.15). 교수님은 '다시 한 번, 힙 삽입은 마지막에 넣고 업힙, 시간은 로그 n.'이라고 강조했다 (p.15). 진단에서 확인된 대로 부모가 더 크면 교환하지 않고 정지하며, 이는 p.15의 삽입 절차와 일치한다 (p.15).

**핵심**

- 삽입 = 새 항목을 마지막 위치(배열의 끝)에 넣고 부모와 비교하며 위로 올라감 (업힙, sift-up) (p.15)
- 교환 조건: 부모보다 더 크면 부모와 교환, 부모보다 작으면 정지 (p.15)
- 시간 복잡도 O(log n): 트리 높이만큼만 올라감 (p.15)
- 코드: append 후 while i != 1 and n > self.heap[i // 2]로 부모 값을 내리며 i = i // 2 (p.17)
- 교수님은 삽입 과정을 그림으로 그리라는 문제가 나올 수 있다고 했으므로, 85를 추가해 50, 80과 교환하고 93 아래에서 정지하는 과정을 그려 본다(p.15 그림)

### 힙의 삭제 연산 · 자세히

`지금 당장` `출제 점수 90` `모름`

힙에서 삭제는 항상 루트(최댓값)를 꺼내는 것이다 (p.16). 교수님은 '삭제 과정도 시험에 나옵니다.'라고 강조했고, '삽입이랑 세트로 기억하세요.'라고도 말했다 (p.16). 진단에서 '모르겠어요'를 골라 모름으로 표시했으므로 아래 절차를 처음부터 순서대로 익혀야 한다 (p.16).

절차는 ① 루트를 꺼내고 마지막 노드를 루트 자리로 옮긴 뒤, ② 두 자식 중 더 큰 자식과 비교해 작으면 교환하며 내려가는 것이다(다운힙, sift-down) (p.16). 자료의 예에서는 93을 삭제한 뒤 33을 루트로 옮기고, 80, 62와 교환하며 내려가 결과가 [80, 62, 75, 50, 33, 70]이 된다 (p.16). 코드에서는 delete가 root = self.heap[1]을 저장하고 마지막 값을 pop한 뒤, 더 큰 자식을 선택하고 last >= self.heap[child]이면 멈춘다 (p.17).

시간 복잡도는 O(log n)이다 (p.16). 교수님은 '더 큰 자식과 비교한다, 이 부분에서 실수가 많아요.'라고 경고했다 (p.16).

**핵심**

- 삭제 = 항상 루트(최댓값)를 꺼내는 것
- 절차: ① 루트를 꺼내고 마지막 노드를 루트 자리로 옮긴다 → ② 두 자식 중 더 큰 자식과 비교해 작으면 교환하며 내려간다 (다운힙, sift-down)
- 시간 복잡도 O(log n)
- 자료의 예: 93 삭제 후 33을 루트로 → 80, 62와 교환 → [80, 62, 75, 50, 33, 70]
- 삽입과 세트로 기억한다 (삽입은 업힙, 삭제는 다운힙)

**자주 하는 실수**

- 내려갈 때 두 자식 중 더 큰 자식과 비교해야 하는데 이 부분에서 실수가 많다

### 우선순위 큐와 힙 구현 · 자세히

`지금 당장` `출제 점수 53` `모름`

우선순위 큐는 들어온 순서가 아니라 우선순위가 높은 항목부터 나가는 큐다 (p.18). 연산은 insert(item)와 remove()이며, remove()는 가장 높은 우선순위 항목을 반환한다 (p.18).

구현 방식별로 삽입과 삭제(최댓값)의 시간 복잡도를 비교하면, 정렬 안 된 배열은 삽입 O(1)·삭제 O(n)이고 정렬된 배열은 삽입 O(n)·삭제 O(1)이다 (p.18). 힙은 삽입과 삭제가 모두 O(log n)이다 (p.18). 진단에서 '모름'으로 표시한 '힙으로 구현하는 이유'는 바로 이 점으로, 배열·연결 리스트는 둘 중 하나가 O(n)인 반면 힙은 두 연산 모두 O(log n)이라는 것이다 (p.18).

우선순위 큐의 응용은 운영체제 작업 스케줄링, 다익스트라 최단 경로, 허프만 코딩이다 (p.18). 힙 정렬은 n개를 모두 힙에 넣고(O(n log n)) 하나씩 꺼내면(O(n log n)) 정렬되며, 전체 O(n log n)에 추가 메모리는 거의 없다 (p.18).

**핵심**

- 우선순위 큐 = 들어온 순서가 아니라 우선순위가 높은 항목부터 나가는 큐, 연산은 insert(item)와 remove()
- 힙 구현: insert, remove 모두 O(log n)
- 정렬 안 된 배열: 삽입 O(1)·삭제 O(n) / 정렬된 배열: 삽입 O(n)·삭제 O(1) → 배열·연결 리스트는 둘 중 하나가 O(n)
- 힙으로 구현하는 이유 = 두 연산을 모두 O(log n)으로 맞출 수 있기 때문
- 힙 정렬: 힙에 넣기 O(n log n) + 꺼내기 O(n log n) = 전체 O(n log n), 추가 메모리 거의 없음(제자리 정렬 가능)

**자주 하는 실수**

- 배열(정렬 안 된/정렬된)은 삽입과 삭제 중 하나가 O(n)이라는 점을 놓쳐서, 힙으로 구현하는 이유를 설명하지 못한다(진단에서 '모름'으로 표시한 부분)
